# Chrome 扩展

在 Chrome 打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，选择本 `extension` 目录。先启动 API（监听 `127.0.0.1:8765`）。打开职位页面后，可以选择“保存到待整理（不调用 AI）”把来源和正文持久化到本机草稿；若网络失败，扩展会在本次浏览器会话内按 FIFO 保留最多 20 份捕获，并沿用各自的幂等键重试。可以选择“重试保存待处理捕获”继续，也可以确认后“放弃全部待保存捕获”。也可以使用“把当前页加入解析队列”，该路径仍使用已配置模型、后台队列、候选重复确认和部分成功协议。弹窗可以随时关闭，重新打开会恢复进行中、待核对和失败任务。切换到其他职位标签页可以继续创建任务。待核对任务可逐项修改，也可选择多个任务批量添加；重复候选默认不会进入批次，必须先单独核对并勾选“仍然添加”。扩展文件更新后，需要回到 `chrome://extensions` 点击“重新加载”。

## 解析模型与失败自动切换

每个任务开始解析时确定所用模型，优先级为：弹窗顶部“解析模型”下拉的选择 > 设置页“模型池与路由”（自动选择开启时在所有启用模型间轮询；关闭时使用“默认模型”）。任务会记住实际使用的配置。

解析失败时（认证失败、限流、超时、无效输出、连接错误等模型侧问题），任务自动切换到下一个尚未尝试过的启用模型重试，卡片上以灰色提示显示“第 N 个模型解析失败，自动切换下一个模型重试”；所有启用模型都失败后才标记为失败。本地服务未启动、模型未配置等与模型无关的错误不会触发切换。手动“重试”沿用原模型，再次失败后仍会自动切换。

任务卡和核对页会显示阶段、从 `extractStartedAt` 到 `extractFinishedAt` 的解析耗时、累计尝试次数、当前/最终模型，以及“本次解析请求用量”的输入/输出 token。token 未由后端返回时显示“未返回”，合法的 0 会保留为 0；失败或重试会清除上一轮 telemetry，失败尝试的 token 不会累加到下一次请求。模型展示只保存配置 ID、显示名、provider 和 model，不保存 API Key 等凭据。旧任务和没有 telemetry 的旧后端响应仍可继续使用。

扩展仅申请 `activeTab`、`scripting`、`storage`、`alarms`，并仅允许访问本机 `127.0.0.1:8765`/`localhost:8765` API；不会持续监听标签页或读取历史。旧任务摘要与结构化草稿使用 `chrome.storage.local` 恢复；旧解析队列的原始正文/选中文本只在排队和解析期间进入 `chrome.storage.session`，解析成功后立即删除。无 AI 保存路径的原始正文只在本次浏览器会话暂存，成功保存后由本机 API 持久化到 `ImportDraft`；它不会写进 `chrome.storage.local`。待保存 FIFO 达到 20 份后需先重试或放弃已有捕获，避免继续占用会话存储。
