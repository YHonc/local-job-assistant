# 隐私与发布边界

## 本地保存

SQLite 保存岗位、申请、邮件摘要、清洗资料和应用设置。密钥、邮箱授权码及 Push 地址保存在系统 keyring；浏览器扩展在本地/会话存储中保存任务状态与草稿。数据库备份应作为个人资料管理。

## 外部访问

使用模型解析时，会把相关网页或邮件文本发送到用户配置的模型服务。IMAP 同步连接配置的邮箱，Push 连接配置的通知服务。用户应根据资料敏感程度选择服务与功能；仅使用本地岗位管理不需要配置模型或邮箱。

## 版本控制

以下内容禁止进入公开 Git：数据库及 WAL/SHM、邮件原文、个人岗位导出、API Key、环境配置、浏览器资料、日志、截图、备份、个人提示词与开发对话文档。

`.gitignore` 忽略上述常见产物，并默认忽略所有 Markdown；仅放行根 README、架构说明、扩展 README 和明确列出的公开文档。任何位置的 `AGENTS.md`、`SKILL.md`、提示词 Markdown 都不在公开白名单内。源码内置的通用提取模板和设置功能仍是应用的一部分；用户自定义提示词存于本地数据库或 `local/`。

历史计划、交接与原型可归档到 `local/archive/`。旧开发分支仅保留在本地，首次开源使用独立初始提交；不能只靠删除当前文件来清除历史中的私有内容。

启用 `.githooks/pre-push` 后，推送前会检查完整可达历史。常见秘密格式检查无法识别所有个人信息；公开前仍应审阅暂存差异与提交树。若秘密已泄漏，应立即撤销或轮换相关凭据，再处理远程历史。
